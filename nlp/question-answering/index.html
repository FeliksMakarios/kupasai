Bagaimana Model Menemukan Jawaban

Model tidak memilih satu label, melainkan memprediksi dua posisi: token awal dan token akhir jawaban. Sebuah linear layer di atas hidden state menghitung skor (logit) untuk setiap token menjadi awal atau akhir span.

Contoh nyata dari Modul 11: pertanyaan "How much music can this hold?" pada konteks tentang MP3 — model cenderung memberi skor tertinggi pada "1"/"6000" untuk start dan "MB/minute,"/"hours" untuk end, sehingga jawaban terekstrak "6000 hours".

Coba klik token lain untuk melihat bagaimana span jawaban berubah — ini persis cara kerja torch.argmax(start_logits) dan torch.argmax(end_logits) di notebook.

    Dua Cara Mengatasi Keterbatasan

    Sliding window mengatasi konteks yang melebihi batas token model: teks dipecah jadi beberapa window yang saling tumpang tindih (diatur oleh stride) agar jawaban yang berada di perbatasan window tidak hilang.

    RAG (Retrieval-Augmented Generation) mengatasi keterbatasan extractive QA yang hanya bisa mengutip teks persis: retriever mengambil dokumen relevan, lalu LLM men-sintesis jawaban baru berdasarkan konteks tersebut — bukan sekadar memotong span.

    Jawaban RAG di atas asli dari pipeline Haystack + Qwen2.5-1.5B-Instruct pada dataset Wikipedia "Seven Wonders of the Ancient World".
